3. Investigación Previa

¿Qué dice el reporte oficial del bug y cuál es su estado?

El bug fue reportado originalmente en 2012 por el usuario "slacka" y ha sido confirmado. El estado actual es "CONFIRMED" en el sistema de Bugzilla de Apache OpenOffice. El reporte indica que OpenOffice pierde el formato al importar archivos .doc de MS Word 2003/2007 con estilos avanzados y nuevas líneas.

¿Existen bugs relacionados o duplicados?

Sí, el Issue 119269 fue marcado como duplicado de este bug (119268). Esto sugiere que el problema fue reportado por múltiples usuarios, lo que indica su relevancia y frecuencia de aparición.

¿Sucede en otras versiones o configuraciones?

El bug ha sido confirmado en:

  • Apache OpenOffice 3.3 (versión original del reporte)
  • Apache OpenOffice 3.4.1 (Revisión 1372282) - confirmado por Nicolas en 2012
  • Sistemas operativos: Windows 7 y Linux

¿Cambia el comportamiento al modificar datos u opciones?

Según la investigación de Nicolas, el problema está relacionado con un carácter especial de nueva línea (VT - Vertical Tab) que MS Word utiliza. Si se copia y pega este carácter específico de Word a OpenOffice, el problema persiste. Sin embargo, si se presiona Enter para agregar una nueva línea normal en cualquiera de los programas, el alineamiento correcto se mantiene.

¿Qué evidencia permite establecer cómo debería funcionar el programa?

La evidencia proviene de:

  • Comparación directa con Microsoft Word 2003/2007, donde el formato se mantiene correctamente
  • Documentación de importación de OpenOffice, que especifica que los archivos .doc deben mantener su formato original
  • Expectativas razonables del usuario de que un documento importado mantenga su apariencia original

4. Prueba y Reproducción

Precondiciones

  • Tener Apache OpenOffice 3.3 o superior instalado
  • Tener acceso a un archivo .doc de MS Word 2003/2007 con estilos avanzados y texto centrado con saltos de línea manuales
  • Tener Microsoft Word 2003/2007 instalado para comparación (opcional pero recomendado)

Pasos de Reproducción

  1. Descargar o crear un archivo .doc de MS Word con estilos de encabezado (Heading 1-5) y texto centrado que contenga saltos de línea manuales (Shift+Enter)
  2. Abrir el archivo en Microsoft Word 2003/2007 y observar el formato correcto (texto centrado mantenido en todas las líneas)
  3. Cerrar el archivo en Microsoft Word
  4. Abrir el mismo archivo en Apache OpenOffice Writer
  5. Observar que las líneas después de un salto de línea manual pierden el centrado y aparecen con indentación incorrecta
  6. Comparar visualmente ambas visualizaciones para confirmar la diferencia

Frecuencia

El defecto aparece en el 100% de los intentos cuando se importan archivos .doc con las características específicas mencionadas (estilos de encabezado y saltos de línea manuales en texto centrado). Es reproducible consistentemente.

Configuraciones Probadas

  • Versión 3.3 en Windows 7 - Bug reproducible
  • Versión 3.3 en Linux - Bug reproducible
  • Versión 3.4.1 (Rev. 1372282) en Windows 7 - Bug reproducible
  • Archivos de prueba: Documentos .doc de MS Word 2003/2007 con estilos Heading 1-5

📸 Evidencia

Archivo adjunto original: ParagraphCenterBug.doc (84 KB) - documento de prueba que demuestra el bug

Captura de pantalla: alignment_bug.jpg (50.53 KB) - muestra visualmente la diferencia entre Word y OpenOffice

Análisis técnico: Notepad++ detecta que el carácter de nueva línea es un "VT" (Vertical Tab, código ASCII 11) en lugar de un salto de línea normal

5. Resultado Esperado y Resultado Actual

Resultado Esperado (Oráculo)

Al importar un archivo .doc de MS Word con texto centrado y saltos de línea manuales, Apache OpenOffice Writer debería:

  • Mantener el formato de centrado en todas las líneas del párrafo
  • Preservar los estilos de encabezado (Heading 1-5) correctamente
  • Interpretar los caracteres de nueva línea de manera consistente con MS Word
  • Producir una visualización idéntica o sustancialmente similar a la de MS Word

Resultado Actual

Lo que realmente sucede al ejecutar la prueba:

  • El filtro de importación de OpenOffice interpreta incorrectamente el carácter VT (Vertical Tab) como un salto de párrafo
  • Las líneas después de un salto de línea manual pierden el centrado
  • Aparece una indentación incorrecta en las líneas afectadas
  • El formato del documento difiere significativamente de la visualización en MS Word
  • Solo los párrafos completos (nuevos párrafos creados con Enter) mantienen el centrado correctamente

⚠️ Evidencia del Fallo

Visual: La captura de pantalla "alignment_bug.jpg" muestra claramente que en MS Word el texto "www.xpnet.com" aparece centrado, mientras que en OpenOffice aparece con indentación incorrecta.

Técnico: Análisis con Notepad++ revela que el carácter entre líneas es VT (ASCII 11), un carácter que OpenOffice no interpreta correctamente como un salto de línea suave.

Consistencia: El problema es reproducible al 100% en las versiones 3.3 y 3.4.1 en Windows y Linux.

7. Análisis de Riesgo y Severidad

Evaluación de Impacto

  • Alcance y cantidad de personas afectadas: Alto. Cualquier usuario que importe documentos .doc de MS Word con estilos de encabezado y texto centrado con saltos de línea manuales se verá afectado. Esto incluye usuarios corporativos, estudiantes y profesionales que migran de MS Office.
  • Costo o impacto por fallo: Medio. El usuario debe corregir manualmente el formato, lo que consume tiempo y puede causar frustración. No hay pérdida de datos, pero sí pérdida de productividad.
  • Frecuencia y condiciones de aparición: Alta. El bug es reproducible al 100% en las condiciones específicas. Afecta a una funcionalidad de uso común (importación de documentos).
  • Pérdida o corrupción de información: Baja. No hay pérdida de contenido de texto, solo de formato. La información semántica se mantiene.
  • Bloqueo o indisponibilidad: Baja. El usuario puede continuar trabajando, aunque con formato incorrecto. No bloquea la funcionalidad del programa.
  • Alternativas para continuar trabajando (workaround): Disponible. El usuario puede:
    • Usar el formato nativo ODT en lugar de .doc
    • Corregir manualmente el formato después de importar
    • Usar LibreOffice en lugar de OpenOffice
    • Evitar el uso de saltos de línea manuales en texto centrado
  • Extensiones a otras configuraciones: El bug afecta múltiples versiones (3.3, 3.4.1) y sistemas operativos (Windows, Linux), lo que indica un problema profundo en el filtro de importación.
  • Resultados de pruebas de seguimiento: El bug persistió por al menos 2 años (2012-2014) sin corrección, lo que sugiere dificultad técnica o baja prioridad asignada.
